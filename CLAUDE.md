# CLAUDE.md

Guidance for coding agents in this repository (`AGENTS.md` is a symlink to this file).

## Overview

Personal homepage/blog (lkwplus.com) on the `astro-erudite` v2 template: Astro 7, **no UI framework and no CSS framework** — native CSS with autonomous custom elements, Radix Colors and Utopia fluid spacing. Package manager is **bun**; Node >= 22.12.0.

## Commands

```bash
bun dev              # Dev server at http://localhost:4321
bun run build        # astro check + build to dist/
bun run preview      # Preview the production build
bun test             # Unit tests (src/lib/**/*.test.ts, bun:test)
bun run check:links  # Internal-link check over dist/ (build first)
bun run format       # Biome format (writes); format:check to verify
bun run astro ...    # Astro CLI (e.g. `bun run astro check`)
```

`bun dev`/`bun run build` first run `scripts/prebuild.ts`: it syncs the self-hosted Umami tracker into `public/headache.js` and writes the homepage cat to `src/assets/cat.jpg` (both gitignored). The tracker is non-fatal offline (falls back to `src/assets/headache-fallback.js`); the cat is the committed `src/assets/cat-default.jpg` unless the `CAT_IMAGE` env var (URL or local path, e.g. a Workers Builds variable) overrides it for that build, falling back to the default if it can't be read. The refresh button still fetches a random cataas cat client-side.

**Checks.** No linter — Biome is format-only (double quotes, semicolons as-needed, 2-space indent, 80 cols). CI (`.github/workflows/ci.yml`, actions pinned to SHAs, Bun pinned by `.bun-version` — bump it deliberately) runs two parallel jobs — `check`: `bun audit --prod --audit-level=high` (an ignore goes in the workflow with its reason; none today), format:check, `bun test`, `astro check` with the strict tsconfig, each run even when an earlier one fails; `build`: prebuild, `astro build --force` with Astro's image cache restored, and `check:links`. A newer push to a PR cancels its older run, never on `main`; docs-only changes (README, LICENSE, CLAUDE.md, `.claude/`) skip CI. `check:links` requires every `#fragment`, same-page ones included, to name an id, flags `[](…)` targets in the `.md` artifacts that still point into the source tree, and fails any link to the old `blog.lkwplus.com` host (those URLs 404 or redirect, and read as external). `overrides` in `package.json` lift transitive deps to patched releases (`fflate`, `lodash-es` exact-pinned by their parents; `source-map-js`, which an in-range update leaves at the old lockfile entry; `vite`, exact at 8.3.4 for GHSA-587h-7wmj-h5pm until astro's range carries it); drop one once its parents' locked versions carry the fix. `bun run build` runs `astro check`, which skips the vendored tracker (`public/`, `headache-fallback.js`). `.githooks/pre-commit` formats staged files (installed by `prepare` on `bun install`). `@biomejs/biome` is exact-pinned at 2.5.14: 2.5.15 re-breaks inline elements in `.astro` templates onto their own lines, which changes rendered whitespace (a space inside the byline's `first` aside, around icons) — re-check the built HTML before moving it. `@astrojs/check` needs TypeScript 6 — don't bump `typescript@^6` to 7 until the native compiler exposes the programmatic API. Likewise the `@expressive-code/plugin-*` packages stay on 0.42 until `satteri-expressive-code` moves off `expressive-code ^0.42` (two cores otherwise), and `Mermaid.astro` pins `layout: "dagre"`: Mermaid 12 defaults to ELK, a 1.4 MB chunk that also re-lays every diagram (that chunk and Mermaid's ~630 kB parsers are why `chunkSizeWarningLimit` is 1500). `satori` stays on 0.33 for now: 0.34–0.57 shipped in two weeks (Oct 2026) with rendering changes (synthesized bold/italic, `fontVariant`), so move it once releases settle and the OG cards are compared before/after.

**Deploy.** A static-assets-only Cloudflare Worker (`wrangler.jsonc`, custom domain `lkwplus.com`) via Workers Builds, so **pushing to `main` is the deploy**. `trailingSlash: "never"` + `html_handling: "drop-trailing-slash"`: links, canonicals and the sitemap all name `/about`. `public/_headers` sets baseline security headers (HSTS without subdomains, nosniff, Referrer-/Permissions-Policy, a CSP of `frame-ancestors`/`base-uri`/`object-src` only) and marks `/_astro/*` immutable; `public/_redirects` holds the old URLs and turns the 307 of a trailing slash into a 301. Neither runs under `bun dev`: the `worker` config in `.claude/launch.json` (`wrangler dev`, port 8787) serves `dist/` the way Cloudflare does.

**Fonts are subset.** Sans is **Inter 4.1**, mono **Geist Mono**. `src/assets/fonts/Inter-Variable.woff2` and `GeistMono-Variable.woff2` cover Latin through Latin Extended-A, punctuation, arrows, maths, box drawing (mono) and every character in content and source — no Cyrillic/Greek/Vietnamese. The `wght` axis is cut to **400–600** (Inter) and **400–700** (Geist Mono); the `@font-face` ranges in `fonts.css` match, so a weight outside them clamps. Inter's `opsz` keeps **14–24** (the browser picks the cut from the size, so a 24px title is in the display cut), and it keeps only default shaping plus `tnum`, **`--font-sans-features`** (`ss01 ss03 ss04 cv11`: open digits, serifed I/tailed l, round quotes, single-storey a) and `case` (in `--font-label-features`, on uppercase labels), set on `body` and reset to `normal` on `code`/`kbd`/`samp`/`pre` and other mono text (Geist Mono has its own `ss01`–`ss04`). To widen weights, add a script or a feature, change both and re-run `bun scripts/subset-fonts.ts` (re-subsets from the full fonts pinned in git history). The OG cards' Latin face, `og/InterDisplay-*.ttf`, has those features frozen into its cmap (Satori applies none); the command is in `src/lib/og.ts`. `STIXTwoMath-Regular.woff2` (MathML) is cut by range — Latin, Greek, operators, arrows, delimiters and the italic/bold/double-struck/script/sans/mono alphabets — by the same script. Likewise `src/assets/fonts/og/` (Noto Sans SC for OG images: GB2312 + kana + every content character): a title with a new character needs `bun scripts/subset-og-fonts.ts`.

## Architecture

- **`src/consts.ts`** is the personalization surface: `SITE`, `NAVIGATION`, `SOCIALS`, feed endpoints (`API`, `MISC`, `NOW`, `MEMOS`, `TOKENS`, …), `FLIGHTS`, `USES`. Edit there before touching components.
- Path alias `@/*` → `./src/*`.
- Head tags: `MetaPage.astro` / `MetaPost.astro`, both through `MetaOpenGraph.astro` (`og:*` plus `twitter:card` only — X falls back to the `og:` tags). A post's `twitter:creator` is its first author's `socials.twitter`.
- One shared layout, `src/layouts/Layout.astro`, which imports the site-wide stylesheets in cascade order. Two are not site-wide: `feed.css` (live-section surfaces, readouts and skeletons) is imported by each component that draws a live section, and `typography-math.css` by the post page.

### Markdown pipeline

No remark/rehype. Markdown goes through **Sätteri** (Rust) configured in `astro.config.ts` with `syntaxHighlight: false`. Plugins live in `src/lib/markdown/`; add one as a `defineMdastPlugin`/`defineHastPlugin` there and list it in `src/lib/markdown/index.ts` (`mdastPlugins`/`hastPlugins`, which `astro.config.ts` hands to the processor):

- mdast: `callout.ts` (`:::note[Title]`), `steps.ts` (`:::steps` around an ordered list → `<step-list>`: mono step numbers in the margin joined by a hairline, the items still Markdown), `file-tree.ts` (`:::file-tree` around a nested list → `<file-tree>`: each item's first word, `code` or **bold** run (bold marks it) is the name, the rest a muted comment; children or a trailing `/` make a directory), `math.ts` (`$…$`/`$$…$$` → MathML via **Temml**), `expressive-code/inline.ts` (`` `code{:lang}` ``), `mermaid.ts`, then `unhandled-directives.ts` last: a `:::x`/`::x` no plugin claimed is reported, and a bare text directive — prose like `注意:abc`, which the directive syntax reads as `:abc` and would drop — goes back to its text (RSS runs it too).
- hast: `external-links.ts` (a full `https://lkwplus.com/…` link becomes root-relative, an internal link), `asides.ts`, expressive-code blocks, `table-scroll.ts` (wraps each table in the `<table-scroll>` that scrolls it, so the table keeps `display: table` and its semantics), `heading-namespace.ts` (subpost-scoped ids), `heading-anchors.ts`.

Astro caches rendered posts in `node_modules/.astro/data-store.json`, invalidated only when a post or `astro.config.ts` changes, so `bun run build` passes `--force` (a full content rebuild every time; the collection is small). Under `bun dev`, restart with `bun run astro dev --force` after editing a plugin's own file, or old HTML stays.

- **Asides** (`asides.ts`, pure half `wrapAsides` tested): wraps each outermost balanced `( … )`/`（ … ）` in prose in `span[data-aside]`, dimmed to `--prose-aside`. Skips pairs split across element boundaries, unbalanced ones, a half-width `(` right after a letter/digit (`f(x)`), and code/`pre`/`kbd`/maths/SVG/headings.
- **External links** get a trailing `span[data-site-icon]`: the host's Simple Icons logo (`SITE_ICONS` in `site-icons.ts`, matching subdomains too; SVGs in `src/assets/icons/sites/` with `<title>` stripped) or a generic arrow, drawn by CSS `mask` in `site-icons.css`, glued to the link's last word with `span[data-glue]`. Each slug needs both the SVG and a CSS rule — the build fails on a missing file and `site-icons.test.ts` checks both.
- **Code blocks**: Expressive Code via `satteri-expressive-code`, with its page-wide CSS/JS stripped from the blocks and served instead by the `expressiveCodeAssets` Vite plugin as `virtual:expressive-code.css`/`.js`, which `[...id].astro` imports (one hashed, cached file for every post).
- **Mermaid** only with `mermaid: true` frontmatter: the plugin turns fences into `<pre class="mermaid">` and `[...id].astro` loads `Mermaid.astro` (any post in a series opting in loads it for the page); otherwise fences stay code. The renderer is imported only when a diagram nears the viewport; if the chunk fails the diagrams show their source (`data-failed`, retried on `online`), and theme re-renders run one at a time.

### Content

Collections in `src/content.config.ts`: `blog`, `authors`, `friends`, globbed with `**/[^_]*.md` — **a `_` prefix hides a file or folder**.

- A post is `src/content/blog/<slug>/index.md` with colocated `assets/`. Sibling `.md` files are **subposts** (`isSubpost(id)` = id contains `/`), rendered with the parent as one continuous series page with one table of contents (`src/pages/blog/[...id].astro`). `src/lib/content.ts`: `getPosts()` (top-level, drafts filtered), `getSubposts()` (ordered by `order`, then date), `getSeries()` — each published post followed by its subposts, **the one answer to "what is published"**: post pages, `/blog/<id>.md`, OG cards, llms.txt, RSS, About and `getTags()` all read it, so a subpost under a draft parent appears nowhere. RSS emits one item per series (subposts appended under their titles). The sitemap excludes subposts and tag pages.
- Frontmatter: `title`, `description`, `date`, `authors` required; `updatedDate`, `order`, `tags`, `image`, `draft`, `mermaid`, `ai`, `lang` optional.
- **`lang`** (BCP 47): when absent, `postLang()` infers it with `detectLang()` (`src/lib/lang.ts`, tested) — mostly-Han prose is `zh-CN`, else `SITE.locale`. A post page's `<html lang>` is its parent's; English chrome on it (skip link, nav, footer, byline, tags) carries `lang` back to `SITE.locale`. On English pages post titles carry `titleLang()`.
- **`/blog/<id>.md`** (`[...id].md.ts`, `postMarkdown`) serves each entry's reconstructed frontmatter + body, with `./assets/…` rewritten to published URLs through a **lazy** `import.meta.glob` + `getImage()` with no options (the same transform the page requests, so no duplicate asset; eager would ship every colocated image). `CopyMarkdown.astro` copies it (prefetched on hover/focus so the clipboard write stays inside the click's activation); `MetaPost.astro` links it as `rel="alternate"`; `/llms.txt` indexes these, `/llms-full.txt` concatenates them, and `/rss.xml` renders the same body (`postBody`) to full-text HTML with only feed-safe plugins (`feedCallouts`, `feedLists` — steps and file trees back to plain lists — Temml; no Expressive Code) through `feedHtml()` (`src/lib/markdown/feed-html.ts`, tested), which absolutizes URLs.
- **`ai: true`** puts an `AI-assisted` credit (the Claude mark in its coral, then the words) beside the names in the byline (`Byline.astro`), the same in lists and the post header; the blog index shows the mark after the title. Write `popover="auto"`/`"hint"`, never bare `popover` — Astro renders it as `popover="true"`, an invalid value that falls back to manual (no light-dismiss).
- **Lengths** are `countWords()` (`src/lib/lang.ts`, tested: each Han character a word, plus Latin words and numbers, code included) through `postWords(chain, post?)` in `content.ts` — a series' first post counts the series, a subpost itself. Link previews, OG cards and About read it; the `/blog` ledger prints `postMinutes()` instead (`readingMinutes()`: 400 Han characters or 230 Latin words a minute, from the same count) over a bar of the words.
- **`/fixtures`** (`src/pages/fixtures.astro` over `src/fixtures/fixtures.md`, noindex, out of the sitemap, feeds and llms.txt) holds every Markdown feature and its edge cases, drawn as a post draws them: check a pipeline or prose change there first, light and dark, wide and phone.
- **Site links**: `src/lib/site-links.ts` (tested, Astro-free so `astro.config.ts` imports `SITE_ORIGIN` from it) recognises links into the site (`sitePath`, `linkedPostId`, `postLinks`). `LinkPreview.astro` on post pages writes a card for each post the bodies link to (build time, JSON in the page) and shows one `popover="hint"` anchored to the hovered or keyboard-focused link; no anchor positioning or a touch pointer means no preview.
- The post header: byline row (author, `PostDates.astro`, Copy Markdown as an icon chip at its end — the Markdown mark copies, an arrow opens), then tags on a row of their own (`PostTags.astro`).
- `TableOfContents.astro`: one `--progress` property drives both the desktop and mobile progress rings; several entries may carry `data-active`, only the first gets `aria-current="location"`. It drops entries whose target section is `hidden`.

### Styling

Hand-written CSS in `src/styles/*.css`.

- **Cascade layers**: every global stylesheet opens with the same order, `@layer reset, tokens, prose, layout, primitives, feeds, feeds.sections, feeds.states;`, and wraps its rules in one of them (`fonts`/`color`/`shape` are `tokens`, typography/callouts/site icons `prose`, `icon-button`/`bar` `primitives`, `feed.css` and `tokens/*.css` `feeds.sections`, the Tokens skeletons `feeds.states`). Component `<style>` blocks are unlayered and win over all of them. Unlayered on purpose: `[hidden]`, `.sr` and the reduced-motion block in `reset.css`, the overrides of Expressive Code's own (unlayered) CSS in `typography-block.css`, the view-transition rules in `layout.css`, the `forced-colors` block in `color.css`, and `print.css`.
- **No colour literal outside `color.css`**: `src/lib/tokens-audit.test.ts` fails on a hex/`rgb()`/`hsl()`/`oklch()` in any `.css`, `.ts` or `.astro` `<style>`/`<script>` outside an allow-list (`color.css`, the Tokens vendor palette in `tokens/shared.css`, `MetaHead.astro`'s `theme-color`, `og.ts`), checks `og.ts`'s colours still match the light theme, and checks every value in those allowed files is a Radix Colors value (`@radix-ui/colors`, a dev dependency) except Claude's coral (`BRAND` in the test). A new colour is a token in `color.css` first. Mermaid reads its palette from the tokens. The code themes are Vitesse moved onto Radix (`src/lib/markdown/expressive-code/radix-theme.ts`, tested, through Expressive Code's `customizeTheme`): syntax at a hue's step 11 or Olive 11/12, opaque, with `minSyntaxHighlightingColorContrast: 0` so nothing nudges them off their steps; marked lines are alpha fills with no coloured left bar.

- **Every colour is a Radix Colors step** (`color.css`: Olive, Olive A, Grass, Grass A as `light-dark()` pairs), used by Radix's convention — 1–2 backgrounds, 3–5 fills (`--muted`/`--muted-hover`/`--muted-active` = neutral A3/A4/A5), 6–8 borders (`--border` A6, `--border-strong` A7), 9–10 solids, 11–12 text. The neutral is read only through the `--neutral-*`/`--neutral-a*` aliases (pointing them at `--gray-*` turns the site back to pure grey; Gray stays defined for that) — never write `--olive-*` or `--gray-*` in a rule. No `color-mix()`: a tint is an alpha step. Two text colours only, `--foreground` (12) and `--muted-foreground` (11). The heatmap scale `--heat-0…4` is neutral 4 then Grass 7/8/9/11 (beside it `--down-1…4`, neutral A5–A11, a return's losses in ink); the one accent is `--accent-fill` (Grass 10 in light, 9 in dark, shapes) and `--accent` (Grass 11, text), for the TOC ring, selection, `--ring` (focus) and live-data marks — not link hovers (those underline in ink). On a `color-gamut: p3` screen the Grass steps take Radix's P3 values (`color(display-p3 …)`, after the sRGB ones in `color.css`; the audit reads the first, sRGB, definition). Callout titles are their hue's step 12 in light, 11 in dark. `prefers-contrast: more` raises secondary text and lines a step; `forced-colors` gives tiles a system-coloured edge and keeps data marks' own colours. The one colour outside Radix is Claude's own coral: `--brand-claude` `#d97757` (the Tokens Anthropic hue as well, `#cc785c` in dark), kept by choice. `--brand-spotify` is Green 9/10, `--logo-ground` Gray 1 for logo tiles, and the Tokens vendor palette (`shared.css`) Radix steps near each brand hue, picked so the blue-to-violet seven stay 0.06 apart in OKLab.
- **Type: four sizes, no more** (`typography.css`): `--step--2` 12px (labels, axes), `--step--1` 14px (interface text, meta), `--step-0` 16px (reading, section headings at `--font-weight-strong`), `--step-1` 24px (a page's title and its hero figures). Nothing below 12px; hierarchy past that comes from weight, colour and space. Inline code is a step below its text (`--step--1` in reading text, `--step--2` in 14px contexts: tables, file trees, h5/h6, figcaptions), never an `em` fraction. Prose tables have no frame, so their first and last columns lose their outer padding and sit on the text's edges. **Utopia** `--space-*` tokens for space.
- **Lines are hairlines**: borders, rules and chart grid strokes use `--hairline` (0.5px); only focus rings (2px) and data marks are heavier. Charts share `shape.css`'s `--chart-*` tokens (series stroke, thin ghost/level stroke, dot halo, benchmark and level dashes, `--chart-ghost`, `--chart-grid`). No box shadows. Corners from `shape.css` (4px controls/tags, 6px buttons/thumbnails, 8px tiles), nested ones concentric (outer = inner + padding). Motion: `--duration` 250ms with `--ease` (ease-out) for the few state changes that animate; hovers, charts, readouts and skeletons don't.
- **Autonomous custom elements** (`<page-grid>`, `<post-meta>`, `<movies-feed>`, …) styled by element selector. Component styles live in the `.astro` `<style>`; anything that reaches runtime-built DOM needs `:global()` or an `is:global` block nested under the element.
- Index pages open with `PageTitle.astro` (the h1); it and a post's h1 share `typography.css`'s display tokens (`--step-1`, `--font-weight-display`, `--tracking-display`, which `:lang(zh)` relaxes — tracked-in Han touches). `:lang(zh)` also gets `text-autospace`, a looser prose line-height and emphasis dots under `em`/`i` (no italics anywhere); `--font-sans` names the platform CJK faces after Inter. Code blocks take the tile corner (`--radius-lg`). Compact post lists are `PostList.astro` (home, 404); `/blog` is a ledger (sticky year, mono date, length bar) and `/tags` a back-of-book index.
- Visually hidden text is the global `.sr` class (`reset.css`).
- Theme: `ThemeToggle.astro` switches with transitions off for one style pass (a transitioning `light-dark()` colour otherwise keeps the old scheme), and landing on the system's scheme clears the stored choice. `MetaHead.astro` keeps `theme-color` in step.
- An image's caption is an emphasised line right under it (`*…*` in its own paragraph): `typography-block.css` sets it small, muted and centred, without the emphasis dots.
- Images use `image.layout: "constrained"` (Markdown ones too) with `responsiveStyles: false`: srcsets everywhere, layout CSS ours.
- The sidebar nav marks where you are with a hairline rail hung in the gutter (`Sidebar.astro`): the current entry's stretch in ink, a hovered one's in grey, no underline and no accent; on the phone's row the stretch lies under the word. Five entries (`NAVIGATION`); an entry's `also` files other paths under it — `/tags` is Blog's, its crumbs nested there, and `/blog`'s title row links to it (`PageTitle`'s `aside` slot).
- 12-column grid (sidebar / content / TOC) collapsing to one column below `64rem`, where the sidebar becomes a top bar showing only the logo and nav (no crumbs). Between `64rem` and `76rem` the TOC is its phone bar, sticky at the head of the content column, and the column takes the TOC's columns back up to `--measure`. The footer carries a mini `PostStrip` (newest lit, linking to `/blog`) except on post pages and home (`<Layout strip={false}>`) and below 30rem. `print.css` (unlayered, last) prints in light without the chrome.
- `reset.css` blockifies `svg`, so anything mixing an icon and text on one line must be `inline-flex`.
- Page transitions are CSS-only cross-document view transitions (`layout.css`, under `prefers-reduced-motion: no-preference`); no `ClientRouter`, so every navigation is a full load. The sidebar (`view-transition-name: sidebar`) swaps without animating. Switching themes cross-fades the whole page through `document.startViewTransition` (`ThemeToggle.astro`; not under reduced motion), with `data-theme-fade` on `<html>` lifting the sidebar's name for its length so it fades too. `<details>` open and shut at once. The TOC rings follow a scroll timeline through a registered `--progress` (write the animation as longhands: the minifier folds a shorthand plus `animation-timeline` into one `animation`, which drops the timeline); the script sets `--progress` only where scroll timelines are missing.
- Container queries are used only where the column's width diverges from the viewport's (the sidebar takes its cut from 64rem, the TOC from 76rem): Uses, the Movies wall, the home Now bento, the Portfolio table. Not for a readout, which would have to measure itself.

## Live data

Every live section reads **cf-workers-api** (sibling repo `../cf-workers-api`), one Worker at `https://api.lkwplus.com` (`API`). Each service serves a precomposed snapshot at `/<service>/site` (open CORS, `no-cache` + ETag → cheap 304s). None of it is build-time data.

- **`/misc` loads its five feeds from one `GET /misc`** → `{flights, movies, music, portfolio, switch}`, each a service's `/site` body or `null`. `miscSection()` (`src/lib/client/misc.ts`) shares one fetch among the sections asking within 30 s of each other (load, and each reload round); each component still decodes and caches its own section, and a `null` fails only that section. Pages preload their endpoint (`<link rel="preload" as="fetch" crossorigin>`).
- **`swr()`** (`src/lib/client/feed.ts`) is the one load path: paint any cached copy from **localStorage** (any age), always refetch, deliver both to the same idempotent renderer. Payloads are validated before caching and before use (a bad one goes to the fallback). Cache keys carry the schema version (`tokens:site:v16:…`) and a write sweeps other versions of the same feed. `feed.ts` also holds the day/time helpers every feed shares — `dayInstant()` (a calendar day as noon UTC), `shiftDays`, `daysBetween`, `monthDay`, `relativeTime()`, the one "3m ago" (whole units rounded down), and `formatMinutes()`, the one duration (`45m`, `2h 37m`, from 100 hours `1,797h`; Tokens, Flights and Switch all print through it) — the decoder primitives (`isRecord`, `isCount`, `isCalendarDay` — a day that exists, round-tripped, not just the shape), `fetchJson` with timeout, `safeHttpUrl()` — the trust boundary for every remote href/image URL — and `calendarDay()` (today in Asia/Shanghai).
- **`keepFresh({ tick, reload })`** (`feed.ts`) is the one clock: `tick` every minute while visible and on tab return, for anything relative to now ("3m ago", Online, countdowns); `reload` every 5 min and at midnight. Every live section reloads, a failed first load included; a renderer wrapped in `whenChanged()` (`feed.ts`) skips a payload identical to the one it last drew, so a reload that brings nothing new rebuilds nothing. Nothing else runs `setInterval`. A cached payload can be days old, so text that says "today" compares against `calendarDay()`, never the payload's `today` alone (the payload's `today` is the snapshot's newest day — Tokens' default pick, Switch's heatmap end — and a "Today" label re-checks on the tick).
- **Body/fallback.** A section's slot shows its body or its fallback; `settle()` (`feed.ts`) flips both and clears `aria-busy`, and every successful render calls it, so a reload after a failed first load brings the section back.
- **Versioned contracts.** Every payload carries `schemaVersion`; each decoder (`isSite`) accepts only its `SITE_SCHEMA_VERSION` and is pinned by a captured `*.site-fixture.json` + test, mirrored producer-side in cf-workers-api (`SITE_VERSION`). On a shape change, bump both and refresh the fixture from the live endpoint: **the worker ships first**, and the page shows its fallback for the minutes in between.
- **Layering** (every feed): the `.astro` component owns markup, skeletons and styles; `src/lib/client/<feed>.ts` (or `tokens/`) is the pure, DOM-free, unit-tested data layer where every render *decision* and every printed string lives; `src/lib/client/<feed>-feed/` (`tokens-dashboard/` for Tokens) is the runtime — `index.ts` mounts and loads via `swr`, `render.ts` etc. build DOM with `el()` (`src/lib/client/dom.ts`). Renderers are `replaceChildren`-idempotent.
- **Readouts** (`dl.readout`, `feed.css`) are the shared summary grid (Music, Switch, Flights, Tokens): two or four cells across, never three. Set figures with `setReadout()` (`readout.ts`), never `textContent` — it splits number/unit runs and is a no-op for an unchanged figure, which keeps SWR repaints still.
- **Heatmap**: `Heatmap.astro` owns markup and the `--heat-cell`/`--heat-gap` geometry (the palette is `color.css`'s); `heatmap.ts` (`mountHeatmap`) renders to fit width. Its `days` must be dense and chronological — the caller's job (`heatmapWindow()` pads Switch). `<Heatmap selectable />` makes cells a picker (Tokens): `stepDay()` maps arrows to the grid's axes (up/down a day, left/right a week) and the pick is announced through a hidden `role="status"`.
- **Skeletons** reserve the loaded height exactly (one per row the list will fill), since anything shorter shifts the page when data lands. `SKELETON_ROWS` (`src/lib/utils.ts`) is only for feeds of unknown length (Memos, Tokens devices).
- **Lightbox** (`Lightbox.astro`, `lightbox.ts`): PhotoSwipe, code-split and loaded on first click (its CSS too, as a `?url` link: a dynamic CSS import would be hoisted into a blocking stylesheet); zooms bare `prose-content` images, `post-banner` and `.memo-shot` (a multi-image memo is one gallery); if PhotoSwipe fails to load, a memo click falls through to its link (the original). The mount makes bare images keyboard buttons (Enter/Space); PhotoSwipe traps and returns focus. Used on post pages and `/memos`.

### Pages and sections

- **Home** (`index.astro`): Profile, Writing (three latest posts, build-time) and **Now** (`Now.astro`, `/now/site`, logic in `now.ts`, runtime in `now-feed/`): a bento of the latest listen (record half out of its `.sleeve`, shared with Music, standing still), the latest film (poster behind a veil in dark so it doesn't dominate), tokens today across the second row — its label over the last two weeks as bars (`tokenBars()`, square-root heights, today in the accent) in a column as wide as the listen's sleeve, so both tiles' words start on one line, and on the right the figure, its cost and messages, and the week's busiest model with its share first (`topModelText()`, the worker's `tokens.top`, named by `modelLabel()`) — and **Portfolio** across the foot: the whole portfolio's /misc 3M window (cut by the worker, so the return is last over first; `portfolioView()`), one ink line with the S&P 500 dashed, `stripCells` day cells and the axis' two ends — on a phone two columns, the poster beside the two figure tiles, the bars hidden and the chart a sparkline. The listen and tokens tiles carry faint cropped Spotify and Claude marks in their bottom-right corners (as do the quota, device and Uses cards), static. Tile sizes come from the grid and fixed chart heights, never from content; a failed load with nothing cached hides the section.
- **`/misc`**: each `h2` is a `SectionHead.astro` with its one source link (`.section-link`, no underline — the owner's call). Sections:
  - **Flights** (`Flights.astro`, `flights.ts`, `flights-feed/`): the payload is the map, not the log (airports, merged routes, airline/aircraft tallies, totals — never a single flight, a flight number or a time). **Flat SVG, not a globe**: d3-geo conic conformal fitted to the airports, redrawn on resize; basemaps in `src/assets/flights/` (`asia.json` preloaded, `world-110m.json` fetched only when a frame leaves the region) are written by `bun scripts/flights-basemap.ts` — re-run it when a flight lands somewhere new. Lists show `FLIGHTS.routes`/`FLIGHTS.named` rows and fold the rest (`fold()`).
  - **Movies**: Letterboxd diary as a poster wall (posters mirrored to `img.lkwplus.com`).
  - **Music**: Koito stats, heatmap and last listens; `/misc` asks for 11 (a lead + two even columns of ten), matching `LISTENS` in cf-workers-api.
  - **Switch**: catalog ranked by lifetime play time, each row a bar with the recent share in the heatmap's green. Playtime is time in games (the worker's `daily_games`), not console time. Prices/titles come from the worker.
  - **Portfolio** (`Portfolio.astro`, `portfolio.ts`, `portfolio-feed/`): the portfolio kept in Ghostfolio, as **returns, never amounts** — per account a time-weighted growth index (cf-workers-api chains it; money in or out never moves it), holdings by weight plus cash's weight, daily closes of every holding and of VOO (labelled S&P 500), and per account its best days (`best`: newest first, each beating every day after it, read off the worker's daily index; `bestDay()` takes the earliest dated after a range's start, so ALL is answered daily though its axis is weekly). The hero figure is the range's return with only the range under it (no "All accounts" over the whole portfolio's deck); the readout is what it hides — Last session, vs S&P 500 (the benchmark's return in its note, two decimals), Max drawdown, Best day. The axis is US market sessions (daily for the last year, weekly before), so any range is two values divided and the ranges (1W 1M 3M YTD 1Y ALL) are the page's: `availableRanges()` drops one that would reach past the account's start and so repeat ALL. One ink line with the benchmark as a dashed ghost rebased onto it; the strip under it is the same line in day/week/month cells (`grainFor`), gains in the heat greens and losses in ink (`--down-1…4`) — **no red anywhere**, the site keeps one colour, and a down figure is muted with a true minus. The chart is a `role="slider"` (arrows, Home/End) whose scrubber drives the hero figure and lights its strip cell. Accounts (a segmented control with each broker's mark) and ranges share one toolbar above the hero. The holdings are a table by weight (`view()`): ticker and full name in Inter, the range's sparkline, latest price, **average cost per share** (the worker's `cost`; the only per-position money figure, and a price, never an amount), weight and the **position's own return** (Ghostfolio's ROI — gain over the sum of the buys, the setting kept off ROAI, whose time-weighted denominator inflates a recent position) — the sparkline and the return each coloured by its own sign. The table reads its own width (`container-type`): the sparkline goes first, then the cost folds under the price. A row opens in place (`fillPanel`, facts from `holdingFacts()`): the price with its move as a tinted figure, then sector and country as outlined tags and the site with an external arrow on the line under them, the price line against an unlabelled dashed cost level with the gap washed green above and grey below and the first buy dotted, its range tabs with the key to both marks (cost, first buy) on the same row, a four-cell readout (avg cost, vs cost, last session, held) and the 52-week band with price and cost on it; it also lights its allocation segment. Cash is a row per currency marked with its flag (`CASH_FLAGS`, square PNGs in `src/assets/flags/`; a currency without one gets a banknote). Logos are the Worker's mirrored logo.dev copies in rounded-square tiles on white, a monogram for one that fails. The brokers' marks (`account.logo`) sit over the hero figure as a small overlapping deck (`fillKicker`); picking an account folds the others away, and the tiles persist across draws so that animates.
  - **Uses** (`Uses.astro`): static `USES` from `consts.ts`, grouped by where things live; icons are a `Record<UsesIcon, …>` of vendored Lucide SVGs, so a missing icon fails the build.
- **`/memos`** (`Memos.astro`, `memos.ts`, `memos-feed/`): latest Mastodon statuses from `/memos/site` as a year-grouped thread. Status HTML is Mastodon's own, so `memos-feed/sanitize.ts` (allow-list, needs `DOMParser`) is the security boundary; every URL goes through `safeHttpUrl`.
- **`/tokens`** (`Tokens.astro`, `tokens/`, `tokens-dashboard/`, styles in `src/styles/tokens/`): AI token-usage dashboard — Quota, Activity (heatmap doubles as day picker for the day panel), overview/trend/breakdowns, Patterns, Devices.
  - The service owns model/provider id mapping; the page never guesses a vendor from a model name (it reads `byModel[].providers`).
  - Patterns: when the current streak is the record, the Longest card becomes **Previous best** (`computeFacts().previous`) and the current one reads "longest so far", so the two never repeat each other.
  - Quota cards are *reported* data and must admit their age: per-card `capturedAt`, a window past its reset reads `reset 1h ago` (muted, like any foot) rather than a stale percentage, times shown in **Asia/Shanghai** (the collector's zone, which buckets every calendar day). The section re-renders every minute.
  - `PLACEHOLDER_IDS` (`unknown`, `<synthetic>`) are dropped everywhere, so shares may not sum to 100%.
  - Device kinds (backdrop icons) come from `TOKENS.devices` in `consts.ts`; the payload has no hardware info.
  - Decoded but deliberately not drawn: `extraUsage`, `mcpServers`.
  - Styles: one file per renderer module, all nested under `tokens-dashboard` (runtime DOM), the skeletons sit in the `feeds.states` layer, so they win over section rules whatever the import order. Skeletons here are sized to the real payload (the quota card is above the fold).
  - AI brand icons are Lobe Icons mono SVGs in `src/assets/icons/ai/` (`aiIcon()`), `<title>` stripped — a nested `<title>` would shadow the row's own tooltip.
- **`/about`**: build-time blog stats (`countEntryWords`) in `about.astro`'s frontmatter; About this site is a colophon (`<dl>`, hairline rows, Inter and Geist Mono specimens side by side at one size, the build day inked below as a date stamp).
- **Timeline**: `timeline(series, lit, { related })` in `content.ts` marks every post, oldest first, as lit, sharing a tag with the lit ones, or other. OG cards (`og.ts`) end in it; `PostStrip.astro` draws it at a post's end (inside `PostColophon.astro`: the post's short address sits in the strip's slot, centred under the two years, and copies the full URL on click, a hovered cell's title takes its place, and `LICENSE` from `consts.ts` closes it centred; each cell links to its post) and, `mini`, inside the home page's all-posts link (the listed posts lit).
- **Copying** goes through `copyText()` (`src/lib/client/copy.ts`): Copy Markdown and the post-end address share its `data-state`, live-region and reset handling.
- **Home cat** is a print on a small stack (`cat-figure`): a 3:2 photo on paper (white, a grey print in dark) at a slight random tilt, captioned "Cat as a service #" and a random four-digit serial; a refresh fades the new print in (250ms) at a new tilt.
